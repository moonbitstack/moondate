Date

pub(all) struct Date

A day on the proleptic Gregorian calendar.

Proleptic means the Gregorian rules are applied before 1582 as well, which is what every interchange format in reach assumes and what makes arithmetic over the whole range uniform.

pub fn Date::isocalendar(Self) -> (Int32, Int32, Int32)

The ISO 8601 week date: the year the week belongs to, the week number, and the day of the week with Monday as 1.

The year is not always the calendar year. A week belongs to the year that holds its Thursday, so the first of January can fall in the last week of the year before — which is exactly the case a hand-rolled week number gets wrong.

pub fn Date::isoweekday(Self) -> Int32

The day of the week with Monday as 1 and Sunday as 7.

[Date::weekday] counts from Sunday as 0, which is what cron and C's tm_wday use; ISO counts from Monday as 1. Both are here because both are asked for, and picking one silently is how an off-by-one gets into a schedule.

Moment

enum
pub(all) enum Moment

A point in time, in one of the four shapes a format names.

TOML 1.0.0 has exactly these four and gives them these meanings; RFC 3339 defines only Zoned. The distinction is not decoration: Plain is a wall clock, which is what an alarm or an opening time is, and turning it into an instant needs a zone nobody has supplied.

  • Zoned(date~ : Date, time~ : Time, zone~ : Zone)
  • Plain(date~ : Date, time~ : Time)
  • Day(date~ : Date)
  • Clock(time~ : Time)

pub fn Moment::strftime(Self, StringView) -> String

A moment written by a format string of % directives.

The directives are the ones C89 defines, less the two that need a locale (%c, %x, %X are the C locale's) and the one that needs a zone database (%Z writes UTC or the offset, never a name like CEST, because a name cannot be recovered from an offset).

%Y %y %m %dyear, two-digit year, month, day
%H %I %M %S %fhour, twelve-hour, minute, second, microseconds
%p %j %a %A %b %BAM/PM, day of year, day and month names
%z %Zoffset as +HHMM, and UTC
%G %V %u %wISO year, ISO week, ISO weekday, weekday from Sunday
%%a per cent sign

pub(all) enum Zone

How far the clock is from UTC, in minutes east of it.

Utc and Offset(0) are both midnight-at-Greenwich, but they are not the same thing to write down: RFC 3339 §4.3 gives -00:00 to a timestamp whose offset is unknown, and Z to one that is genuinely UTC.

pub fn asn1(StringView) -> Moment raise Refused

An ASN.1 UTCTime or GeneralizedTime (ITU-T X.680 §47), as DER writes them.

This is how a certificate spells its validity. DER requires the Z and whole seconds; UTCTime's two-digit year is read as RFC 5280 §4.1.2.5.1 says — 49 and under are 2000s, 50 and over are 1900s, which is not the same rule HTTP uses.

pub fn http(StringView) -> Moment raise Refused

An HTTP date read (RFC 9110 §5.6.7).

The preferred IMF-fixdate, and the two obsolete forms a recipient must still accept: RFC 850's Sunday, 06-Nov-94 08:49:37 GMT and asctime's Sun Nov 6 08:49:37 1994. A two-digit year is read as RFC 6265 §5.1.1 says: 69 and under are 2000s, 70 and over are 1900s.

pub fn parse(StringView) -> Moment raise Refused

An expression, in the five-field form crontab(5) defines or the six-field form that puts seconds in front.

┌───────────── second (0-59, six-field form only)
│ ┌───────────── minute (0-59)
│ │ ┌───────────── hour (0-23)
│ │ │ ┌───────────── day of month (1-31)
│ │ │ │ ┌───────────── month (1-12 or JAN-DEC)
│ │ │ │ │ ┌───────────── day of week (0-7 or SUN-SAT, both 0 and 7 being Sunday)
* * * * * *

Each field takes *, a number, a range a-b, a step */n or a-b/n, and a comma-separated list of those. ? reads as *, which is how a scheduler spells the day field it is not using.

The shorthands @yearly, @annually, @monthly, @weekly, @daily, @midnight and @hourly are the ones crontab(5) lists. @reboot is not here: it names an event rather than a time, and this package answers when something fires, not why.

expr StringView
pub fn strptime(StringView, StringView) -> Moment raise Refused

A moment read by a format string of % directives.

The directives are the ones [Moment::strftime] writes. Literal characters in the format must match the text exactly, except that whitespace in the format matches any run of whitespace, which is what C's strptime does and what makes a format survive a double space.

The result is Zoned when the text carried an offset, Plain when it carried a date and a time, Day when only a date, and Clock when only a time — the same four shapes [parse] answers with.

Cron

struct
pub(all) struct Cron

A parsed expression: which values of each field it fires on.

Each field is a bit set, so asking whether a moment matches is six bit tests rather than a search. star_day and star_week are kept because the two fields interact — see [Cron::matches].

  • seconds : Int64
  • minutes : Int64
  • hours : Int32
  • days : Int32
  • months : Int32
  • weekdays : Int32
  • star_day : Bool
  • star_week : Bool
Methods
pub fn Cron::matches(Self, @moondate.Moment) -> Bool

Whether m is a moment this expression fires on.

The day-of-month and day-of-week fields are or-ed when both are restricted, which is Vixie cron's rule and surprises everyone once: 0 0 13 * 5 is the thirteenth *or* any Friday, not Friday the thirteenth. When one of them is * they are and-ed, which is why 0 0 13 * * is only the thirteenth.

m @moondate.Moment
pub fn Cron::next(Self, @moondate.Moment) -> @moondate.Moment?

The first moment strictly after m that this expression fires on.

None when it never does. An expression can name a day that does not exist — 0 0 30 2 * is the thirtieth of February — so the search is bounded at four years, which is past any leap-year cycle a real schedule turns on.
