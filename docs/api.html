pub fn Date::isocalendar(Self) -> (Int32, Int32, Int32)

The ISO 8601 week date: the year the week belongs to, the week number, and the day of the week with Monday as 1.

The year is not always the calendar year. A week belongs to the year that holds its Thursday, so the first of January can fall in the last week of the year before — which is exactly the case a hand-rolled week number gets wrong.

Moment

enum
pub(all) enum Moment

A point in time, in one of the four shapes a format names.

TOML 1.0.0 has exactly these four and gives them these meanings; RFC 3339 defines only Zoned. The distinction is not decoration: Plain is a wall clock, which is what an alarm or an opening time is, and turning it into an instant needs a zone nobody has supplied.

  • Zoned(date~ : Date, time~ : Time, zone~ : Zone)
  • Plain(date~ : Date, time~ : Time)
  • Day(date~ : Date)
  • Clock(time~ : Time)

pub fn Moment::instant(Self) -> (Int64, Int32)?

The instant, as whole seconds past 1970 and the nanoseconds after them.

The two are apart because a count of nanoseconds runs out in 2262, and because a zone whose offset is not a whole second puts the nanoseconds of the instant at odds with the nanoseconds on the clock: 15:23:30.123456789-00:00:00.000000100 is 100 nanoseconds earlier than its clock says.

pub fn Moment::isoformat(Self, sep? : Char, fraction? : Int32, offset? : Bool, zone_name? : Bool) -> String

The moment as ISO 8601 text, which is what [Show] writes.

sep is the character between the date and the time, T by default; any character works, and a space is what a log line wants.

fraction is the number of fractional-second digits, 0 to 9, truncated. Left out, it writes as many as the value needs and none for a whole second, which is Temporal's auto.

offset writes the zone the moment carries, Z for UTC and ±HH:MM for an offset; false leaves the zone off, which is Temporal's offset: "never".

zone_name follows the offset with the name the zone is filed under, in brackets: 2026-11-01T01:30:00-04:00[America/New_York], which is Temporal's timeZoneName: "critical" and the only way the text keeps the name as well as the instant.

Zone

enum
pub(all) enum Zone

How far the clock is from UTC.

Utc and Offset(0) are both midnight-at-Greenwich, but they are not the same thing to write down: RFC 3339 §4.3 gives -00:00 to a timestamp whose offset is unknown, and Z to one that is genuinely UTC.

Offset counts minutes; Named counts seconds and carries the name the zone is filed under, so VV and a Go layout's MST have something to write.

  • Utc
  • Offset(Int32)
  • Named(ZoneName)
  • Precise(Int64)
Methods
pub fn Zone::abbrev(Self) -> String

The abbreviation written for the zone: EST, GMT, +0530.

A named zone read from text that carried no abbreviation falls back to the numeric spelling, which is what a fixed offset writes anyway.

pub fn Zone::minutes(Self) -> Int32

How far east of UTC the zone is, in minutes, rounded towards zero.

A named zone whose local mean time is not a whole number of minutes loses the remainder here, which is what the %z forms write and what every other implementation writes for those years.

pub fn Zone::name(Self) -> String

The name the zone is filed under: EST5EDT for a POSIX rule, the path in the database for a named zone.

ZoneName

struct
pub(all) struct ZoneName

A zone named by a database, read at one instant.

The offset and the abbreviation are the ones in force at the instant the moment carries, which is what makes a Zoned a value: it can be compared, written and moved to another zone with no database in reach. Crossing a transition is a question for the rules, so a moment that has to survive one goes back through @zone.Tz::moment.

The offset is in seconds east of UTC, because a zone's local mean time before standard time was adopted is not a whole number of minutes: New York ran 4:56:02 behind Greenwich. Offsets in whole minutes are what [Zone::Offset] carries, and [Zone::seconds] puts both on the same footing.

pub fn Cron::matches(Self, @moondate.Moment) -> Bool

Whether m is a moment this expression fires on.

The day-of-month and day-of-week fields are or-ed when both are restricted, which is Vixie cron's rule and surprises everyone once: 0 0 13 * 5 is the thirteenth *or* any Friday, not Friday the thirteenth. When one of them is * they are and-ed, which is why 0 0 13 * * is only the thirteenth.

None when it never does. An expression can name a day that does not exist — 0 0 30 2 * is the thirtieth of February — so the search is bounded at four years, which is past any leap-year cycle a real schedule turns on.

Fold

enum
pub(all) enum Fold

Which side of a fold a wall clock lands on.

Most zones move their clocks twice a year, so one hour of the year happens twice and another never happens at all. Asking a zone for an instant from a wall clock therefore has three defensible answers and one that refuses.

Compatible is what Python's fold=0 and Temporal's disambiguation: "compatible" both do: the first of two repeated hours, the second of two skipped ones. Earlier and Later pick by instant. Python's fold=1 is Later for a repeated clock and Earlier for a skipped one.

OffsetPolicy

enum
pub(all) enum OffsetPolicy

How a field edit keeps the offset that was in force before the edit.

Prefer is the default: the instant the old offset named is kept when that offset is still the one the zone has at the new reading, and when it is not, [Fold] decides. Ignore goes straight to the zone's rules. Use keeps the old offset whatever the zone says, so a change that fell in between moves the reading — the instant does not move, but the date and time and the offset in force do. Reject is the offset that refuses: a reading the old offset no longer covers is an error, even when the zone would have answered it, which is the one case the disambiguation is not the one to decide.

ZonedDateTime

struct
pub(all) struct ZonedDateTime

A date and a time that already names an instant, carried in a zone.

The instant is the point on the line — epoch seconds and nano nanoseconds past 1970 — and the zone is what the clocks read at it. The two together are the value Temporal calls a ZonedDateTime: move it to another zone and the instant does not move, only the reading does; add a duration and the instant moves by it, whatever a day happens to be here.

What [@moondate.Moment] carries is a Zone — a name with the offset in force at that instant beside it. That is a value that can be written and compared with no database in reach, but it cannot cross a change, because a change is a question for the rules. This type is for that: it keeps a Tz, the readings and the rule that carries on past them, so a step that lands on the other side of a change reads the new offset back from the rules rather than carrying a stale one forward.

let zone = @tzdata.load("America/New_York") let zoned = ZonedDateTime::of(2026, 3, 8, hour=2, minute=30, zone~) // 02:30 never happens, so the compatible answer is the later instant zoned.isoformat() // 2026-03-08T03:30:00-04:00[America/New_York]

The zone it is built in is what it is filed under. A wall clock that is Ambiguous or Skipped is answered by [Fold]; under Reject it raises rather than guessing. A field that is out of range is refused as [Refused::BadDate], the calendar and the clock's own refusal carried here.

pub fn system() -> @zone.Tz raise Refused

What TZ says, and /etc/localtime when it says nothing — the two answers every other library's localtime gives, in that order:

  • TZ empty: UTC, which POSIX says outright rather than by omission.
